# 记账本桌面应用 — 打包修复记录

## 问题：打包后 App 无法启动（静默退出，exit 143 → 0）

### 根因 1：`require('electron')` 在 ES Module 中不存在
**文件**：`src/electron/main.js`  
**原因**：package.json 设置 `"type": "module"`，所有 .js 都是 ESM，但 `const { dialog } = require('electron')` 使用了 CommonJS 语法。`require` 在 ESM 中未定义，模块解析时立即崩溃（没有任何输出，因为 crash 发生在 JS 运行之前）。  
**修复**：将 `require('electron')` 替换为 `import { dialog } from 'electron'` 放在文件顶部。

### 根因 2：db.js 使用 `require()` 加载 better-sqlite3
**文件**：`src/electron/db.js`  
**原因**：同样的 ESM 问题，`require(libPath)` 在打包后调用失败：`require is not defined`。  
**修复**：改用 `await import(libPath)` 动态导入 better-sqlite3 平台入口 `lib/darwin-arm64.js`。

### 根因 3：electron-builder `files` 过度排除嵌套 node_modules
**文件**：`electron-builder.json`  
**原因**：原配置使用 `!node_modules/**` 排除全部 + 显式 include 部分顶层包，导致 `jsonwebtoken` 的嵌套依赖 `ecdsa-sig-formatter`（在 `node_modules/ecdsa-sig-formatter/`）和 `ms`（在 `node_modules/ms/`）缺失。  
**症状**：`Cannot find module 'ecdsa-sig-formatter'` / `Cannot find module 'ms'`  
**修复**：简化 files 配置为 `["dist-vue/**", "dist-electron/**", "src/electron/**", "node_modules/**"]`，包含全部 node_modules。

### 根因 4：db.js 同步导入导致 better-sqlite3 在 asar 内加载失败
**文件**：`src/electron/db.js`（修复前版本）  
**原因**：打包后 better-sqlite3 的 `.node` 文件在 `app.asar.unpacked/` 目录（asar 无法穿透），但 `require('better-sqlite3')` 会尝试从 asar 内加载并失败。  
**修复**：
1. `asarUnpack: ["node_modules/better-sqlite3/**"]` — 解压到 unpacked 目录
2. 动态 `await import(unpackedRoot + '/lib/darwin-arm64.js')` — 平台专用入口加载成功
3. `app.whenReady()` 内延迟导入 — 避免顶层 import 时机问题

## 修复后的文件状态

- `src/electron/main.js`：ESM 风格，延迟动态导入 db.js 和 handlers.js
- `src/electron/db.js`：async initDb()，动态 import better-sqlite3 平台入口
- `electron-builder.json`：简化为包含全部 node_modules
- 产物：
  - `release/mac-arm64/记账本.app` ✅
  - `release/记账本-1.0.0-arm64.dmg` (116MB) ✅
  - Exit 0，无崩溃，DB 28KB（WAL 模式），tables: users + records ✅

## 技术要点

- **延迟导入模式**（在 `app.whenReady()` 内 `await import(...)`）是 Electron ESM 的标准做法
- better-sqlite3 打包后必须从 `app.asar.unpacked` 加载，不能从 asar 内 require
- electron-builder files 配置优先使用 `node_modules/**` 整体包含，而非逐包排除
- `asarUnpack` 会同时在 asar 内保留文件和 unpacked 目录副本（正常行为）
